# Push and a hosted Relay are the only paid services, verified by one central Push Gateway

Timely notifications on a closed phone need APNs or FCM, whose credentials belong to the app's publisher, so a self-hosted Relay cannot send them itself. The project runs one Push Gateway that holds those credentials and charges for it: a store subscription (StoreKit / Play Billing, 14-day free trial) with a generous daily quota. Tiers: **Free** (self-hosted Relay, Chat View, Terminal View, Pairing; notifications only while the app is open), **Push** (adds push notifications) and **Hosted** (adds a Relay the maintainer runs, for people who do not want to self-host); one subscription covers the whole Ring. Users pay for services the maintainer runs, never for features in the code. A heavy Hosted user (five agent Terminals, phone watching all day) costs about $1.50 a month on Cloudflare at worst, because Daemons stream raw Terminal output only for a Terminal View open on screen, and the hosted Relay enforces per-Ring quotas since it cannot see the encrypted traffic it carries. The gateway keeps no accounts: at registration it verifies the store's signed transaction or purchase token and returns a sealed blob holding the device token, tier and expiry, which the Relay presents to request a push; its only state is a per-blob daily counter. The hosted Relay checks the same blob before routing for a Ring. Payloads are sealed to the phone, so the gateway learns only that some device was woken. Android uses the same gateway and subscription as iOS for parity, although a foreground service could reach the Relay for free.

## Considered Options

- **Free push funded by the maintainer.** Rejected: cost grows with adoption and is paid personally.
- **Background polling of the user's own Relay.** Rejected: iOS gives apps no reliable background execution (BGAppRefresh runs when the system decides, often hours apart), and an Android foreground service costs battery, a permanent notification and Play Store justification, breaking parity.
