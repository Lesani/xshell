# Push and a hosted Relay are the only paid services, verified by one central Push Gateway

Timely notifications on a closed phone need APNs or FCM, whose credentials belong to the app's publisher, so a self-hosted Relay cannot send them itself. The project runs one Push Gateway that holds those credentials and charges for it: a store subscription (StoreKit / Play Billing, 14-day free trial) with a generous daily quota. Tiers: **Free** (self-hosted Relay, Chat View, Terminal View, Pairing; notifications only while the app is open), **Push** (adds push notifications) and **Hosted** (adds a Relay the maintainer runs, for people who do not want to self-host); one subscription covers the whole Ring. Users pay for services the maintainer runs, never for features in the code. A heavy Hosted user (five agent Terminals, phone watching all day) costs about $1.50 a month on Cloudflare at worst, because Daemons stream raw Terminal output only for a Terminal View open on screen, and the hosted Relay enforces per-Ring quotas since it cannot see the encrypted traffic it carries. The gateway keeps no accounts and no device registry. At registration it verifies the store's signed transaction or purchase token (or an entitlement token the Ring already holds), and returns two things:

- a push blob sealed to itself (device token, platform, Ring, tier, expiry), which the Relay presents to request a push;
- an entitlement token it signs (Ring, tier, expiry, at most 7 days), which the Relay stores so every device of the Ring can register under one subscription, and which the Hosted Relay checks before routing.

Its only state is per-Ring daily counters (pushes are capped per Ring, not per device) and one record per purchase (App Store original transaction, or the root of a Play purchase-token lineage) binding it to a Ring; every push is checked against the current binding. A binding can move to another Ring at most once per 30 days, so one subscription cannot be rotated across Rings. Payloads are sealed to the phone, so the gateway learns only that some device was woken. The gateway core uses only web-standard APIs and ships with Workers and Deno Deploy adapters, because APNs needs HTTP/2 and Workers' support for it is unverified. Android uses the same gateway and subscription as iOS for parity, although a foreground service could reach the Relay for free.

## Considered Options

- **Free push funded by the maintainer.** Rejected: cost grows with adoption and is paid personally.
- **Background polling of the user's own Relay.** Rejected: iOS gives apps no reliable background execution (BGAppRefresh runs when the system decides, often hours apart), and an Android foreground service costs battery, a permanent notification and Play Store justification, breaking parity.
