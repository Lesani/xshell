# Mobiles reach Daemons through a self-hosted, untrusted Relay with end-to-end encryption

A Mobile observes and steers agents on all of its owner's machines without SSH access to them. Daemons therefore dial out to a Relay the user hosts (designed to fit Cloudflare's free Workers and Durable Objects tier) and stay connected, which gives presence: every machine with a running Daemon shows up. The Relay only joins streams between keys of the same Ring and never sees plaintext; Daemons and Desktops authenticate each other by keys pinned at Pairing and encrypt end to end, so a compromised Relay (or Cloudflare) can drop traffic but cannot read or type into Terminals. This partly supersedes ADR-0002 ("xshell ships no auth or TLS code") and the rule that a Daemon never dials out: SSH remains the transport between a Desktop and a Remote Host it was configured with, the Relay is an additional path, and over it a Mobile speaks only the xshell protocol, with no shell, forwarding or file access.

## Considered Options

- **Relay accounts with TLS ending at the Relay.** Rejected: whoever runs the Relay could read every keystroke and agent output, which is unacceptable for a self-hosted tool most people will run on a third party's edge.
- **Mobile as an SSH client through a devrelay-style tunnel.** Rejected: it grants the phone full shell access to every machine, needs per-host SSH configuration on the phone, and cannot provide presence.
- **SSH protocol over the Relay (Daemon embeds an SSH server exposing only an `xshell` subsystem).** Rejected in favour of Noise (`Noise_IK_25519_ChaChaPoly_BLAKE2s`): the Roster already gives each side the other's static key, so IK connects in one round trip instead of SSH's three to four through the Relay hop, which matters for a phone that reconnects on every wake; it adds no server to the Daemon's attack surface, and the xshell protocol already multiplexes Terminals. Sessions are pairwise per (Desktop, Daemon), never a shared Ring key, so removing a device from the Roster revokes exactly that device.

## Consequences

- A Mobile is a remote control for agents, not a remote shell. The Daemon enforces this from the Roster role: a Mobile may open, attach to, type into, close and Relaunch agent Terminals (skip-permissions included) and read session data, but may not open shell Terminals or pass a `shell_command`, and may not use the file or git methods of `call`. Since an agent the phone can type into can do anything the agent can, this limits what a stolen phone gets directly, not what an agent can do. The phone's real protection is its private key in the Secure Enclave or StrongBox, an app lock with biometrics after idle, and a fresh biometric confirmation for every change of an agent's skip-permissions flag.
