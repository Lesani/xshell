# Headless machines install with one command and update over the Ring

Without SSH (ADR-0016), a Desktop can no longer install or update a Daemon by logging in. A headless machine gets xshell from one pasted command that downloads the Daemon, verifies its checksum, starts it, enables it across reboots and prints the Device Code. Updates travel over the Ring: any Desktop newer than a machine offers to update it, one machine or all at once.

The install script is served from its own name (`get.xshell.sh`), never from the Relay's: the Relay is untrusted by design and an installer is fully trusted, so they must not share a name or a codebase. Builds are produced and verified locally and only hosted on GitHub Releases. Until the first next-generation release the script is fetched from GitHub as well.

## Amendment (2026-11-27): Ring Hosts update themselves from the latest release

A Daemon that can be updated over its link also offers `daemon.update-latest`. On that request it asks the release server (`get.xshell.sh`, overridden by `XSHELL_GET_URL` for tests) for the latest version; when that version is newer than its own, it downloads its own machine type's build and checksum, verifies the checksum, the build stamp and the reported version and build, and installs the build exactly as a staged one. It selects nothing: the Desktop follows with `daemon.upgrade-selected`, with the same trial, watchdog and rollback. A failure leaves the running Daemon and its selection untouched. The request shares the one-update-at-a-time slot with staging and has the same authorization (the local socket, or a Desktop of this Ring).

The Desktop reads the latest version from the same server at start and every 3 hours, never waiting for it; when it is unknown, nothing is offered to these Hosts. A Host with `daemon.update-latest` is outdated only when the latest release is newer than its version (semver precedence); it is never "build differs", and "Use this Desktop's build" is not offered for it. Hosts without the capability (every Daemon up to 1.6.0-rjw.3) still get the Desktop's own build over the link. This applies to Hosts reached over the Relay only: a machine reached through a saved SSH route, and the Desktop's own Local Host, keep their update path. A Ring Host that is also another computer's Local Host may then be replaced by that computer's Desktop with its bundled build; this is accepted. Releases therefore reach Ring Hosts when `get.xshell.sh` points at them, not when a Desktop is updated.
