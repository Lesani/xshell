# Relay enforces membership without granting it

For full computer Desktop adoption and inactivity expiry, the Relay maintains and enforces the signed Roster, but devices still independently verify authorization for membership changes: compromising the Relay must not let an attacker enroll a key. Expiry follows a signed Ring-wide policy configured in Hosts (30 days by default), and authorized clients, including Daemons with narrowly scoped self-removal and expiry-cleanup rights, may rely on the Relay's activity records; we accept that a compromised Relay can cause false expiry and loss of availability rather than making it a membership-granting authority. These are agreed design requirements, not capabilities of the current protocol, which permits only computer Desktops to sign Roster changes.

A Computer Device groups its Desktop and Local Host Daemon for enrollment, revocation, and activity: either identity's connection keeps the unit active. There is no last-device expiry exemption; if all devices expire, recovery requires a new Ring and Pairing again. Policy supports an explicit Never expire option, but increasing or disabling expiry cannot restore an expired enrollment. Mobiles may approve enrollment, explicitly revoke active devices, and change inactivity policy after fresh biometric confirmation, without gaining shell, file, or git access.
